# ai-sandbox-android

The Android client (UC04) for the ai-sandbox kit. Talks to the
[UC03 management server](../README.md#remote-management--the-uc03-mtls-server)
over mTLS. Sideload-only — there is no Play Store release and there
never will be.

## What this app does

- **Onboarding** (UC04-1): scan an invite QR generated by
  `aisandboxctl client invite <name>`, redeem the token via
  `POST /v1/enrollment`, import the PKCS#12 bundle into the Android
  KeyStore as a non-exportable client identity.
- **Cold-start resume** (UC-16): when a valid `ServerProfile` and a
  non-expired client cert are already on disk, a fresh launch goes
  straight to the sessions list — no QR re-prompt. A stale profile
  without a cert (or vice versa, or an expired cert) is wiped and the
  QR scanner is shown for a clean re-enroll.
- **Sessions list** (UC04-2): show `ai-sandbox-N` sessions and their
  state (`running` / `starting` / `stopped`) over mTLS. Filter chips,
  spawn via bottom sheet, delete with optional force.
- **Terminal** (UC04-3): full-screen attached terminal via
  `wss://host/v1/sessions/{n}/stream` (subprotocol `ai-sandbox.v1`),
  docked modifier bar, optional split-pane. AC14 BEL → 150 ms haptic.
- **Foreground service** (UC04-4): `dataSync` ongoing notification
  keeps the WS alive across lock-screen + task-switch.
- **Settings** (UC04-5): server URL + pin + client cert metadata +
  WebSocket diagnostics + a "Simulate cert revoke" test path.
- **Cert-revoke handling** (UC04-7): close-code-4401 → "Identity
  revoked" dialog → re-scan QR flow.
- **Pin-mismatch handling**: any TLS cert change on the server →
  full-screen "Server identity changed" refusal screen with expected /
  observed sha256 hex.

## Build

```bash
./gradlew :android:lint                  # Android lint (JVM-only)
./gradlew :android:test                  # JVM unit tests
./gradlew :android:assembleDebug         # debug APK
./gradlew :android:bundleDebug           # debug AAB
./gradlew :android:assembleRelease       # signed release APK
./gradlew :android:bundleRelease         # signed release AAB (Play AAB format)
```

The release tasks require a signing config — see "Signing" below.

## Architecture

- **Kotlin + Jetpack Compose**, Material 3 Expressive baseline, dark
  theme only.
- **AGP 9.x** ships built-in Kotlin support — the standalone
  `org.jetbrains.kotlin.android` plugin is intentionally NOT applied
  (it fails with "no longer required for Kotlin support since AGP 9.0"
  if added back).
- **Manual DI** via `AppContainer` (a tiny service locator). Hilt is
  not used; AC29 forbids the analytics SDKs Hilt's industry baseline
  typically pulls in via Firebase.
- **OkHttp** for HTTP/2 + WebSocket. Pinned to the server cert via
  `CertificatePinner` configured from the QR's `pin` field at
  enrollment time. mTLS identity comes from the Android KeyStore via
  a hardware-backed (when available) `X509KeyManager`.
- **Crypto provider — BouncyCastle (`bcprov-jdk18on:1.79`)** is
  bundled as a JCE provider so the client can unwrap the modern
  PBES2 PKCS#12 bundles emitted by `server-v0.0.12+` (the JDK 21
  default for `KeyStore.getInstance("PKCS12")` since Java 14+, which
  the stock Android `"BC"` provider does not handle — it has no
  `SecretKeyFactory` registered under PBKDF2 OID
  `1.2.840.113549.1.5.12`). The real provider is registered at
  process start under the distinct name `BC-ai-sandbox-client` (so
  the stock `"BC"` is left untouched) at lowest priority via
  `Security.addProvider`, and `KeyStoreIdentityManager` looks it up
  explicitly via `KeyStore.getInstance("PKCS12", "BC-ai-sandbox-client")`.
  TLS continues through Conscrypt for hardware-accelerated AES/AEAD;
  BC is reserved for the PKCS#12 enrollment-cert import unwrap
  (PBKDF2-HMAC-SHA256 + AES-256 unwrap on the JDK 21 default
  emission). See [UC13](../use-cases/13-android-bouncycastle-pkcs12-import-fix.md)
  for the empirical failure mode and the integration rationale.
- **ZXing** for QR decode in onboarding. Chosen over ML Kit
  specifically to avoid pulling `play-services-mlkit-*` into the dep
  graph — AC29 forbids any `play-services-*` artefact, and the CI
  workflow (`android-ci.yml`) greps the dependency tree to enforce
  this.
- **kotlinx.serialization** for the QR payload + server REST DTOs.
  Wire shapes mirror `server/src/main/java/com/aisandbox/server/api/dto/ApiDtos.java`
  field-for-field.

## Signing

Two signing config sources, in order of precedence:

1. **Environment variables** (CI):
   - `KEYSTORE_FILE` — absolute path to the keystore file
   - `KEYSTORE_PASSWORD` — keystore password
   - `KEY_ALIAS` — alias of the signing key (default `ai-sandbox`)
   - `KEY_PASSWORD` — key password

2. **Local fallback**: `~/.gradle/keystore.jks` (read by AGP when
   `KEYSTORE_FILE` is unset and the file exists; passwords come from
   the env vars above or default to empty).

If neither path produces a keystore, `assembleRelease` / `bundleRelease`
fall back to the debug signing config — fine for local smoke-testing
but unusable for sideload distribution (the partner's phone has a
different debug-signing fingerprint and Android refuses to install the
APK over a previously-installed debug-signed build).

**Backup discipline**: the GitHub release-signing keystore secret needs
an offline backup. There is no way to re-sign an existing APK with a
new key — the operator's recovery path is "issue a new keystore,
re-build under a new package-id, ship to the two devices as a fresh
install."

## Foot-guns

- **No telemetry, no crash reporter.** If the app crashes on the
  partner's phone, you don't find out unless they tell you. Plan
  accordingly (the partner has the operator's contact details).
- **One server profile at a time.** Re-scanning a QR while a profile
  exists shows a "Replace existing identity?" confirmation; on
  confirm, the old Android KeyStore entry is deleted irrecoverably
  before the new bundle is fetched. A failed re-enrollment leaves the
  device with NO identity — re-scan a fresh invite to recover.
- **Local Android SDK required for local builds.** CI uses
  `android-actions/setup-android@v3`; locally you need
  `cmdline-tools` + `platform-tools` + `platforms;android-36` +
  `build-tools;36.0.0` (or whatever the brief currently pins). Set
  `ANDROID_HOME` or drop a `local.properties` next to `settings.gradle.kts`
  with `sdk.dir=…`.
- **The terminal-rendering surface is a v0.1 placeholder.** It renders
  raw UTF-8 of the PTY stdout in monospace and auto-scrolls; ANSI
  escape sequences pass through unparsed (so colours render as
  garbled escapes). The proposal calls for Termux's `TerminalView`
  (Apache 2.0, source-only); vendoring it is a follow-up. The public
  Composable signature is forward-compatible — swap-in lands cleanly.
- **No analytics-grade backup of the imported cert.** When the user
  factory-resets their phone, the AndroidKeyStore-resident key is
  lost; recovery is "operator runs `aisandboxctl client invite` again."
  This is by design — backing up a hardware-backed key is, by
  definition, exfiltrating it.

## CI

- [`.github/workflows/android-ci.yml`](../.github/workflows/android-ci.yml)
  — PRs + pushes to main on `android/**`. Runs lint, JVM tests, debug
  APK + AAB builds. AC29 guard: fails if any `com.google.android.gms`
  or `play-services-*` shows up in `:android:dependencies`.
- [`.github/workflows/android-release.yml`](../.github/workflows/android-release.yml)
  — `android-v*` tag triggers signed APK + AAB build + GitHub Release.
  Keystore decoded from base64 secret to tmpfs (`/dev/shm`) and wiped
  on job teardown.
